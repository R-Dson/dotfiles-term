# Documentation Style Guide

## Voice and Tone
- **Professional but Approachable**: Avoid overly academic language.
- **Direct**: Use the imperative mood for instructions ("Click", "Run", "Open").
- **Inclusive**: Use gender-neutral pronouns (they/them).

## Formatting Rules
- **Headings**: Use sentence case for headings (e.g., "Getting started", not "Getting Started").
- **Emphasis**: Use **bold** for UI elements and `backticks` for file names/variables.
- **Lists**: Use numbered lists for sequential steps and bullet points for features/requirements.

## File Specifics
- **README.md**: Must contain: Introduction, Prerequisites, Installation, Usage, and License.
- **API.md**: Must include: Endpoint, Method, Request Body (JSON), and Example Response.
